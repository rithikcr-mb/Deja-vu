A compact guide to the local proof of concept

DEJAVU App Map

DEJAVU turns a study topic into a short lesson and battle. Missed answers are saved as learning events; those events later shape the mentor and the final boss.

One action, through the app

When an answer is wrong, the app records the mistake before it changes health or shows the result. That ordering keeps the learning history reliable even if saving fails.

The same saved concepts and events are retrieved later for the mentor, boss weak spots, and weakness review.

Reference route in the code

  1. dejavu/routes.py — answer_battle_question checks the submitted choice and asks Python to grade it. Wrong answers are persisted before health changes.
  2. dejavu/services/battle.py — grade_answer and apply_answer decide correctness, damage, and the next battle state.
  3. dejavu/db/repository.py — record_mistake_in_transaction links an append-only mistake event to a normalized weak concept. The route tests check that a replay saves only once and persistence happens before feedback.

This is a reference route, not a claim that we toured the editor together.

To change this, start here

  • Battle damage or round flow: dejavu/services/battle.py
  • What the battle displays: dejavu/templates/battle.html
  • Question shape and content checks: dejavu/services/ai_schemas.py and dejavu/services/content.py
  • Colors and responsive layout: dejavu/static/css/app.css

A practice to reuse

Turn an important behavior into an observable rule, then test the boundary where it could fail. Here, the rule is “save a wrong answer once before changing health”; the route tests exercise duplicate submissions and persistence failures. That same pattern helps any app where a user action must be saved before the interface claims success.

Run it again

From the project folder, use fake mode for deterministic examples without a network call:

$env:DEJAVU_FAKE_AI = "true"
python -m flask --app app init-db
python -m flask --app app run --host 127.0.0.1

Then open http://127.0.0.1:5000/. See README.md for virtual-environment setup, seeded demo instructions, and the live Gemini configuration.
